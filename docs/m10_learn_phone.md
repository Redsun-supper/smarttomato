# 二哈 1 代「学手机」

> 工具：`tools/husky_learn_phone.py`（板上 `/root/smarttomato/husky_learn_phone.py`）
> 规格依据：DFRobot 官方 wiki（SEN0305）+ 2020-03-30 物体分类上线公告，2026-10-16 核对。

---

## 0. 🔴 先知道一个冲突：算法互斥

二哈 1 代（SEN0305）**一次只能跑一个算法**，7 种里选 1 种：

| 算法 | 用途 | 本项目现状 |
|---|---|---|
| 人脸识别 | 判在座 | **主程序正在用** |
| 物体分类 | 学手机（可自学） | 要切过去才能用 |

**切成「物体分类」的那一刻，「判在座」就没了** —— 这不是 bug，是模块架构。

所以「学手机」不是加个功能，而是要**换掉主程序的感知方式**。三条路见 §4。

---

## 1. 只要一个「手机」ID

物体分类把镜头前的东西学成**类别 ID**。本项目不需要区分亮屏灭屏，
只要**一个** ID = 手机。识别时只判「画面里有没有检测到手机」。

### 学习是远程的，不用按模块上的键

`command_request_learn_once(id)` 就是「把镜头前这一刻学成 id」，走 I2C 发命令即可。

## 2. 📌 官方规格（这次查证的硬数字）

| 项 | 官方说明 |
|---|---|
| **每类样本量** | **推荐 30 张以上**，"学的越多识别越精准"；未给硬上限 |
| 录入方式 | 模块上「长按学习键不松开」可连续录入多张，松开自动训练 |
| 模型槽位 | **每个算法 5 个模型（槽 0~4）**，一个模型 = 该算法下学过的**全部物体** |
| 多场景用法 | 官方明说：学剪刀石头布存一个模型、学垃圾分类存另一个，**切换模型即可满足多场景，避免重复学习** |
| 坐标 | 物体分类**不输出坐标** —— 框位置固定在屏幕中央，xCenter/yCenter 无意义 |
| SD 卡 | **FAT32**；导入只支持**相同算法**的模型 |

> 关键结论：**白天/晚上分条件，官方推荐的做法是「各存一个模型 + 切换」，
> 而不是塞进同一个 ID**。见 §4 的模型槽位方案。

## 3. 🔴🔴 核心：样本要覆盖亮屏和灭屏，且量要给够

**只在黑屏状态下学习，会学不到亮屏的样子。** 机制原因：

二哈的物体分类是机器学习分类器，它学的是「长什么样」。
黑屏手机 ≈ 一个「黑色矩形」；亮屏手机 = 发光屏幕 + 内容 + 轮廓，视觉差异极大。
只学黑屏 → 模型只认识「黑色矩形」→ **亮屏大概率认不出来**。

### 单个模型内的样本配比（合计 30 张以上）

| 顺序 | 学什么 | 张数 | 目的 |
|---|---|---|---|
| 1 | 亮屏 · 不同 App（锁屏 / 微信 / 游戏） | 15~20 | **主力** —— 特征最丰富，定义「手机」这个概念 |
| 2 | 亮屏 · 换角度（正面 / 稍偏 / 横握）、换距离 | 5~8 | 视角泛化 |
| 3 | 灭屏（黑屏 / 稍偏角度） | 5~10 | 补黑屏状态 |

⚠️ **黑屏别学太多**：它的特征太弱（就是个黑框），学多了模型会把
「任何黑色矩形」都当手机 —— 手机背面、钱包、暗色桌面都会被误判。

⚠️ **`--burst` 期间必须动！** 连续学 30 张的前提是手机在**不断换角度/换 App**。
静止不动学 30 张 = 1 张，白费。

⚠️ **在实际使用的光线下学**：二哈是个摄像头。白天自然光下学出来的模型，
晚上台灯下用会掉准确率。

## 4. 完整操作步骤

⚠️ 顺序不能乱 —— 主程序占着 I2C，必须先让开。

```bash
# 1) 停掉主程序（用精确 PID，别用 pkill —— 会匹配到自己的 shell）
ps -eo pid,args | grep '[m]10_step3'
kill <主程序PID>

# 2) 切到物体分类，先看基线
python3 -u husky_learn_phone.py --check 5

# 3) 学「手机」—— 一个模型内 30 张以上
python3 -u husky_learn_phone.py --burst 1 20      # 亮屏·期间不断换 App/角度
python3 -u husky_learn_phone.py --burst 1 10      # 灭屏·期间晃动换角度

# 4) 起名 + 验证
python3 -u husky_learn_phone.py --name 1 手机
python3 -u husky_learn_phone.py --check 10

# 5) 存模型（断电即丢，必须存 —— 卡必须是 FAT32）
python3 -u husky_learn_phone.py --save 0

# 6) 学完整机 reboot，等约 1 分钟，再拉起主程序
sync; systemctl reboot --no-block
```

### 分条件学习：用模型槽位，不要塞同一个 ID

如果白天/晚上差别大，按官方推荐的做法**各存一个模型**：

```bash
# 白天学完存槽 0
python3 -u husky_learn_phone.py --burst 1 25
python3 -u husky_learn_phone.py --save 0

# 晚上开台灯重新学，存槽 1（先 forget 清空，避免白天样本混进来）
python3 -u husky_learn_phone.py --forget
python3 -u husky_learn_phone.py --burst 1 25
python3 -u husky_learn_phone.py --save 1

# 用时按光线切换
python3 -u husky_learn_phone.py --load 0     # 白天
python3 -u husky_learn_phone.py --load 1     # 晚上
```

优点：每个模型专注一种光线，特征纯、样本量不摊薄。
代价：程序要按时段/光线主动 `load` 切换（写死时间表，或接光线传感器判断）。

⚠️ 中间光线（阴天、傍晚）两个模型都可能认不出 —— 先按一个模型试，漏了再决定要不要分。

### 验证清单（学完一定要逐项试）

跑 `--check 10`，把手机摆成各种真实状态，确认**都出检测框**：

- [ ] 亮屏 · 正面
- [ ] 亮屏 · 微信 / 游戏（换你常用的 App 试）
- [ ] 亮屏 · 横握
- [ ] 灭屏 · 正面
- [ ] 灭屏 · 稍偏角度
- [ ] 换到另一个时段/光线重试一遍

⚠️ **漏了哪个场景就补学那个场景**，然后重新验证 —— 这是个调参循环，不是一步到位。

## 4.5 按键式学习（常驻服务）：按 A 启停，每按 B 学一张

工具 `tools/husky_learn_hold.py`（板上 `/root/smarttomato/husky_learn_hold.py`），
systemd 服务名 **`husky-learn`**。**按官方库接口写**：`command_request_algorthim` /
`command_request_learn_once` / `command_request_blocks` + `read_count("blocks")` /
`read_learned_id_count`，不自己拼协议帧。

> 需要自定义协议（快读、中文起名、批量连学）时用 `tools/husky_learn_phone.py`，
> 它是独立的一次性工具，见 §4。

**为什么不用二哈自己的学习键**：那个键在模块本地，**I2C 协议读不到它的状态**
（协议里没有「读按键」指令，`0x2C` 那个 KNOCK 是心跳不是按键，库里还被注释掉了）。
所以拿 M10 自己的 A/B 键当开关 —— 设备 `/dev/input/event2`（名字 `keyboard_ab`）。

### 按键 code

从设备位图 `KEY=1000050000000` 推出，置位在 bit 28 / 30 / 48：

| 键 | code | 标准名 |
|---|---|---|
| **A** | **30** | `KEY_A` |
| **B** | **48** | `KEY_B` |
| Home | 28 | `KEY_ENTER` |

### 部署 / 启停（本机一条命令）

```bash
cd tools
python deploy_husky_learn.py              # 上传脚本 + 装服务 + 启动
python deploy_husky_learn.py --status     # 看状态 / 日志尾部
python deploy_husky_learn.py --stop       # 停服务（SIGTERM → os._exit，干净退出）
python deploy_husky_learn.py --no-start   # 只部署不启动
python deploy_husky_learn.py --enable     # 额外设开机自启（⚠️ 见 §7.5，慎用）
```

板上等价操作：`systemctl start|stop|status husky-learn`，日志 `/root/smarttomato/learn.log`。
服务单元里固定带 `--no-switch`（模块已在物体分类，切算法是本板的 panic 触发点，见 §7.5）。

### 操作

| 动作 | 效果 |
|---|---|
| **按 A** | 空闲 ↔ 学习 切换（**不会退出进程**，可反复做多轮） |
| **按 B**（学习中） | 学一张到 ID 1，日志打 `[n] 已学 → ID 1` |
| **按 B**（空闲时） | 只提示「先按 A 键」，不误学 |

### 屏幕（240×320）显示什么

服务里有 `Environment=DISPLAY=:0`，用 `unihiker.GUI` + Pillow 直接画，只在内容变化时重绘：

```
学手机 · ID 1
    学习中            ← 学习中=青色 + 顶部青色条；待命=灰色
      12              ← 本次已学张数（大字）
   本次已学（张）
● 看到目标            ← 二哈检测到目标亮绿；没检测到是灰色空心圆
模块已学 ID：1
A 开始/结束   B 学一张
```

`● 看到目标` 是最有用的一行：它说明**当前这一帧二哈确实看到了东西**，
此时按 B 才学得到有效样本；一直是空心圆就说明手机没进画面中心的大框。

### 与旧版的差别

| 旧版 | 新版 |
|---|---|
| 按 A 停止 → 进程退出 → 板子 panic | 按 A 只切状态，进程常驻；退出走 `os._exit` |
| 学的时候看不到状态，只能回头翻日志 | 屏幕实时显示：状态 / 已学张数 / 是否看到目标 |
| 每次只读一个按键事件，连按会丢键 | 一次排空多个事件 |
| 启动就要切算法 | 默认由服务带 `--no-switch`，不碰这条 panic 触发点 |

⚠️ 官方建议每个类别 30 张以上。

## 4.7 官方对「学习一个物体」的要求（查证结论）

## 5. 遗忘：只能整个清空，不能只删单个 ID

🔴 协议里 `forget` **不带任何参数**（`dataLength=0`），官方 wiki 也通篇
**没有「选择性遗忘某一个 ID」的操作**。所以：

- ✅ 脚本：`python3 -u husky_learn_phone.py --forget` → 清空**当前算法下全部**已学内容
- ✅ 模块按键（官方路径，两步）：在算法主界面**短按「学习按键」** →
  屏幕提示「再按一次遗忘！」→ **倒计时内再短按一次** → 完成，
  屏幕中央显示「+」字（回到未学习状态）。反悔就在倒计时内别按任何键。
- ❌ 想只删掉学错的某一个 ID：**做不到**，只能全清重学。

### ⚠️ 所以养成习惯：先 save，再折腾

SD 卡里的模型**不受遗忘影响**（官方原文：「即使删除了当前算法的所有数据，
也可以再从 SD 卡中重新加载模型」）。所以每次改完先存一个槽位：

```bash
python3 -u husky_learn_phone.py --save 0      # 学砸了就 load 0 回来
python3 -u husky_learn_phone.py --forget      # 放心清空重学
python3 -u husky_learn_phone.py --load 0      # 需要时随时恢复
```

分条件学习（白天/晚上各一个模型）时，`--forget` 正好用来清空上一个条件的样本，
避免混进下一个模型。

## 6. 🔴 一个能力边界：只认「有手机」，不认「在玩」

物体分类判的是**画面里有没有手机**，它**不区分手机在手里还是在桌上**。
手机平放在桌角也会被检出，而且物体分类**不输出坐标**，连「在屏幕哪个位置」都判不了。

如果你的目标是「玩手机就提醒」，那还需要姿态/朝向信号 —— 二哈 1 代**没有**。
但如果你只是要「手机别出现在视野里」，那物体分类**恰好够用**。

三条路的取舍：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 物体分类里同时学两类** | ID1=人（判在座） ID2=手机 | 一个算法覆盖「在座 + 有手机」；但「人」靠自学，泛化**远不如**专用人脸识别模型 |
| **B. 只学「手机」**（推荐先试） | 保持人脸识别不变，需要时手动切算法 | 切过去就丢了在座检测，切回来手机又没了 |
| **C. 上二哈 2 代（SEN0638）** | K230 6 TOPS，可同时跑多模型，自带姿态/朝向 + 自学习分类 | 要换硬件（本来就是升级目标） |

先走 **B** 看看「认手机」到底靠不靠谱：手动切过去学，认不准就拉倒，主程序不受影响。
真要「玩手机才提醒」，等 2 代。

## 7. 硬件层面的坑

- **模型断电即丢** → 必须 `--save` 到 SD 卡，开机 `--load` 回来。
- **SD 卡必须 FAT32**。2026-10-16 实测：插上二哈 2 代用过的（多半 exFAT/ext4）卡，
  模块会**卡在启动流程** —— 屏幕亮着、线也紧，但 **I2C 完全不响应**（0x32 消失），
  极易误判成「模块坏了 / 线松了」。**拔卡即恢复**，插卡前先确认格式。

## 7.5 🔴 内核 panic 的定位结论（2026-10-17，反复复现）

### 现象

板子会在**起 pinpong 进程后的几秒到一分钟内**整机重启（SSH 断、约 40 秒恢复）。
`/proc/uptime` 归零 = 真的重启过，不是网络抖动。

内核日志（`journalctl -b -1`）在重启前留下：

```
kernel: config_open 61 count = 1
kernel: SPI1 driver loaded-------------------------
kernel: read gpio state error-----------------
kernel: write fail
kernel: rx_len = 0
kernel: Unable to handle kernel paging request at virtual address ffffff0000008f1e
kernel: Internal error: Oops: 96000004 [#1] PREEMPT SMP
```

即：**gd32v（协处理器）这条 SPI 链路写失败，而 `pinpong_linux_module` 在错误路径上
解引用了野指针 → paging fault**。这是内核模块的 bug，用户态无法捕获，只能规避。

### 三个已确认的触发点

| 触发点 | 证据 |
|---|---|
| **发「切算法」指令（0x2D）** | 5 次崩溃全部落在 `切到「物体分类」…` 之后几秒内 —— 二哈重载模型期间 NAK/拉总线，首包就失败 |
| **进程退出** | 普通 `return` / `sys.exit()` 退出后 15 秒内板子失联；改 `os._exit()` 后同一脚本退出后板子始终在线 |
| **任何 I2C 读失败** | 一次读失败（`write fail / rx_len = 0`）就可能触发，无法预判 |

### 结论与对策

1. **进程必须常驻**：本版所有退出路径走 `os._exit()`，按 A 只切状态不退出。
2. **服务启动时带 `--no-switch`**：模块上手动选好「物体分类」，脚本就不发这条指令；
   手动跑脚本时才由 `--no-switch` 决定切不切。
3. **不要 `Restart=always`**：重启即重新配置 gd32v，容易进「起来就 panic、panic 又重启」的循环。
   服务挂了就整机重启，别自动重试。
4. **整机重启 ≠ 冷启动**：gd32v 由 5V 常供电，`reboot` 不会给它掉电复位。
   一旦它被留在坏状态（例如切算法被打断），**只有拔 Type-C 冷启动**能恢复 ——
   这也是「重启后怎么都起不来，拔电插上就好了」的真正原因。

### 板子起不来的排查顺序

```bash
# 1) 空载稳定吗？（无 pinpong 进程时 uptime 持续增长 = 板子本身没坏）
cat /proc/uptime
# 2) 有没有残留进程占着 I2C？
ps -eo pid,args | grep '[h]usky_learn_hold'
# 3) 模块在不在总线上（这一步不加载 SPI1，安全）
i2cdetect -y 4 | grep 32
# 4) 看上一次崩溃的内核日志
journalctl -b -1 --no-pager | tail -30
```

若第 1 步空载稳定、第 3 步 0x32 在，但一起进程就崩 → **拔 Type-C 冷启动**，
同时把二哈的 4Pin 线也拔插一次（模块被打断在「重载模型」状态时也会一直 NAK）。
冷启动后等约 1 分钟再 `systemctl start husky-learn`。
