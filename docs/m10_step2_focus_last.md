# m10_step2_focus_last.py —— 第 2 段：语音开番茄钟 + 丝滑布局过渡

> ★ **最终版（LAST）** —— 本项目当前实际部署、上板运行的就是这一个文件。
> 命名约定：最终版文件名以 `_last` 结尾，一眼认出哪一版是要用的；中间版本不要用这个后缀。

## 它做什么

在第 1 段（横屏时钟）的基础上加三件事：

1. 语音识别到「开始学习」（`kai shi xue xi`）→ 触发
2. 语音合成回答「好的，开始专注25分钟」→ 出声
3. 屏幕进入番茄钟倒计时 25:00，**时间与日期同步缩小、飞向左上角**，
   倒计时在中央浮现 —— 整个过程缓动插值、逐帧重绘，做到「丝滑」

```
┌─ 待机 ────────────────┐        ┌─ 专注中 ──────────────────┐
│                       │        │ 21:14:35                  │ ← 18px 深青
│      21:14:35         │  ───►  │ 2026年10月13日 星期二      │ ← 14px 次灰
│  2026年10月13日 星期二 │        │                           │
│                       │        │          24:59            │ ← 54px 深青
└───────────────────────┘        │         剩余时间           │
                                 │ ▓▓░░░░░░░░░░░░░░░░░░░░░░  │ ← 底部进度条
                                 └───────────────────────────┘
```

## 「丝滑」是怎么做到的

整个画面只用**一个参数 p ∈ [0, 1]** 描述：

- `p = 0` 纯待机时钟；`p = 1` 纯专注倒计时；中间值 = 过渡帧。
- 时间/日期的**中心坐标**与**字号**都按 p 线性插值，倒计时按 p 淡入，
  所以不存在「跳变」，每一帧都是合法画面。
- p 用 `easeInOutCubic` 缓动 → 起步和收尾柔和、中段快。
- 过渡时长固定（`TRANS_SEC`），每帧按**真实流逝时间**推进 p，
  因此即使帧率波动，动画总时长也不会变。
- 90° 整屏旋转用 `Image.transpose()`（纯内存搬运）而不是 `Image.rotate()`
  （通用仿射变换），单帧省下十几毫秒 —— 这是帧率能上去的关键。

## 文字精灵缓存（性能核心）

行空板 M10 + Pillow 9.0.1 实测：

| 操作 | 耗时 |
|---|---|
| `ImageDraw.text` 渲染一行 62px 时间 | **21 ms** |
| `ImageDraw.textbbox` 量一行 62px 文字 | **7 ms** |
| `img.paste(小图)` | **~1 ms** |
| `img.resize(小图)` | **~2 ms** |

**`draw.text` 极慢、`paste` 极快**，所以把文字渲染成 RGBA 小图缓存，之后每帧只贴。

### ⚠️ 缓存 key 里不能放「逐帧变化的量」

踩过两个坑，都已修：

1. **颜色**：淡入用的「白→青」插值颜色被写进了 key，导致过渡期间每帧都是新 key。
   → 现在精灵一律用**最终颜色**渲染，淡入改成「贴图时按 alpha 合成」：
   白底 + 青字按 alpha 叠加，数学上就等于「白→青」插值，但不产生新 key。
   （alpha 用 256 项查表 + `Image.point`，**不要传 lambda** —— 那会变成每像素一次
   Python 调用，能把 1ms 的操作拖成几十 ms。）
2. **字号**：过渡中字号本来就在逐帧变，也被写进了 key。
   → 现在只缓存**两个端点字号**（它们本来就要用于静止态），中间字号用 `resize`
   缩放得到。顺带好处：字号变成**连续**的，不用再量化到 2px 台阶，动画更顺。

另外淘汰策略从 `clear()` **整个清空**改成**只丢最旧的一批** ——
`clear()` 会把日期/标签这些本该常驻的条目也一起清掉，越算越慢。

## 硬件

| 模块 | 型号 | I2C |
|---|---|---|
| 语音识别 | DFR0715（LD3320） | `0x4F` |
| 语音合成 | DFR0760（V2） | `0x40` |

- 关键词在代码里用**空格分隔的拼音**定义，无需在模块上「学习」。
  例：`("kai shi xue xi", 1)` = 「开始学习」。
  ⚠️ 不要写成 `"kaishixuexi"`（不分音节）—— 模块固件解析不出来，会一次都识别不到。
- 两个模块可共存于同一条 I2C1（地址不冲突），已实测验证。
- 两条语音链路（ASR 轮询线程 / TTS 播放线程）共用总线，而 pinpong 的 I2C
  **不是线程安全的**，所以所有 I2C 访问都用 `I2C_LOCK` 串行化（含初始化）。

### 合成侧的两个坑

1. 库的 `begin(V2)` 结尾会自己 `set_voice(1)`（把音量压到 1），初始化后**必须再设一次音量**。
2. 库的 `wait()` 是**没有超时的死循环**；自己重写时，**`0x41`（开始合成）之后必须
   `sleep(0.1)` 再发状态查询**，否则会打断刚起步的合成 —— 模块秒回空闲，
   表现为「耗时 0.00s」而且完全没声音，**日志上却一切正常、不报任何错**。

## 上板前务必确认

- pinpong 的 I2C 在行空板上很脆弱：**重启后等约 1 分钟**（够 `rc.local` 的
  `anaysis.py` 跑完即可）、**同一次开机只跑一个进程**，否则 I2C 会初始化失败。
- 板子没有 RTC，系统时间默认可能是错的。先对时：
  `date -s '2026-10-13 21:00:00' && hwclock -w`

## 用法

```bash
python3 m10_step2_focus_last.py                     # 正常跑：说「开始学习」触发
python3 m10_step2_focus_last.py --demo              # 8 秒后自动触发一次
python3 m10_step2_focus_last.py --no-voice          # 不初始化语音模块（纯屏幕）
python3 m10_step2_focus_last.py --focus-min 1       # 改成 1 分钟，方便测试
python3 m10_step2_focus_last.py --preview out.png   # 不连板子，把过渡关键帧拼成一张图
```

## 按键（演示 / 调试用）

| 键 | 作用 |
|---|---|
| A 键 | 手动触发一次（等价于识别到「开始学习」） |
| B 键 | 立即结束，回到待机（**幂等**，连按不会重置淡出动画） |

## 远程调试钩子

程序运行期间，在板上 `touch /tmp/step2_trigger` 就等于识别到一次「开始学习」。
这样不用重启进程就能验证（板上 I2C 很脆，重启进程可能让语音模块失效）。
