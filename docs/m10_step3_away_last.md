# m10_step3_away —— 第 3 段：离座检测 + 分级提醒 + 超时暂停番茄钟

> 对应代码：`m10_step3_away.py`（上板最终版改名为 `m10_step3_away_last.py`）
> 设计依据：`DESIGN.md`（设计令牌）+ `prototype_seat_detection.html`（六态评审原型）

---

## 1. 这一段做什么

在第 2 段（语音开番茄钟 + 丝滑过渡）之上加「有人看着你」这件事：

```
二哈识图人脸识别，持续判断「在座 / 离座」
    连续 60 秒没人脸   →  判离座，**番茄钟立即暂停**（回来自动继续）
    60s ~ 3min        →  L1 轻提醒（蓝）
    3min ~ 5min       →  L2 中提醒（琥珀）
    > 5min            →  L3 强提醒（品红，近全屏反色）
    人脸重新出现       →  绿色「欢迎回来」帧 1.5s，番茄钟恢复
```

**不认人**：任意一张脸即算在座（已确认的设计决定）。

---

## 2. 与 DESIGN.md 的一处有意偏离（用户 2026-10-14 指定）

DESIGN.md §4.6 的升级矩阵里，**只有 L3 才「冻结暂停」**，L1/L2 是「运行中」。

用户明确要求「**超过 1 分钟就停止番茄钟**」，因此本实现把**暂停提前到 L1**
（即判离座的那一刻就暂停）。这是唯一一处偏离，代码里也标了注释。

若想退回原设计，改 `AwaySupervisor.update()` 里这一处即可：

```python
if self._tier is None:
    self.n_away_events += 1
    self._away_start = mono
    self.app.pause()        # ← 删掉/加条件，就变成「只有 L3 才暂停」
```

「停止」按**暂停**实现（冻结倒计时，回来自动继续），与已确认设计
「番茄钟判离座即暂停，回来自动继续」一致；不是中止整个番茄钟。

## 4. 代码结构

| 组件 | 职责 |
|---|---|
| `Screen` | 把 `View` 画成一张图（六态都在这里） |
| `View` | 一帧要画什么：`p / remain / total / tier / away_sec / pulse / recover` |
| `FocusApp` | 番茄钟状态机，第 3 段新增 `pause()` / `resume()` |
| `HuskyPresence` | 后台线程轮询二哈人脸识别 → `present` |
| `FilePresence` | 没有二哈时的替代：由 `/tmp/step3_absent` 文件驱动 |
| `Presence` | 对外统一接口：优先二哈，拿不到自动退回文件，**不阻塞启动** |
| `AwaySupervisor` | 把「有没有人」变成「画哪一帧 + 暂停/恢复 + 出不出声」 |
| `VoiceASR` / `Speaker` / `VoiceTrigger` | 复用第 2 段（已修好的超时合成版） |

### 暂停是怎么实现的

`FocusApp` 不再靠「把 `_end` 往后推」，而是冻结：

```python
pause()   →  _paused_remain = _end - now;  _paused = True
resume()  →  _end = now + _paused_remain;  _paused = False
```

`snapshot()` 里**必须先判 `_paused` 再判归零** —— 暂停期间 `_end` 是个过期时间戳，
顺序反了会立刻「时间到」。两个方法都幂等。

## 5. 硬件与踩坑

### 二哈识图（SEN0305，I2C 0x32）

- 驱动 `pinpong.libs.dfrobot_huskylens.Huskylens(i2c_addr=0x32, bus_num=0)`。
- `command_request_algorthim("ALGORITHM_FACE_RECOGNITION")` 切算法后，
  **必须等约 5.5 秒**再读数（本实现用 `HUSKY_WARMUP_SEC`）。
- `read_count("blocks")` 直接给「检测到几个框」；人脸识别里就是**几张脸**，
  `> 0` 即判在座。
- 🔴 **驱动的失败重试会阻塞**：`_write_to_huskyLens` 失败时重试 6 次、
  每次 `sleep(0.5)`，最后抛 `ValueError` —— 总共约 3 秒。
  所以**轮询必须放后台线程**，绝不能在主循环里读，否则画面会卡死。
- 读失败时本实现按「**在场**」处理：宁可漏报离座，也不要误报。

### 和语音模块共用一条 I2C

ASR（0x4F）、TTS（0x40）、二哈（0x32）**三个设备在同一条 I2C1 上**，
地址不冲突。但 pinpong 的 I2C 对象不是线程安全的，所以三者的访问
全部串行化在同一把 `I2C_LOCK` 上（ASR 轮询线程 / TTS 播放线程 / 二哈轮询线程）。

### 调试三条件（沿用，别忘）

1. **重启后等约 1 分钟**再起进程（等 `rc.local` 的 `anaysis.py` 跑完）。
2. **同一次开机只跑一个碰 I2C 的进程** —— 第 2 个进程必失败（SCL 恒低）。
   所以改代码后要**整机 reboot**，再让新程序当第一个进程。
3. 所有要测的步骤写进**同一个脚本、一个进程跑完**。

## 6. 用法

```bash
# 正常跑：说「开始学习」开番茄钟，之后自动监督
python3 m10_step3_away.py

# 调参（测试时把阈值压小，几十秒就能看完整条升级链）
python3 m10_step3_away.py --away-sec 5 --l2-sec 15 --l3-sec 30

# 不用二哈（或没有二哈时），改由触发文件驱动离座
python3 m10_step3_away.py --no-husky
touch /tmp/step3_absent     # 判离座，开始倒计时
rm    /tmp/step3_absent     # 判回座，绿帧 + 恢复计时

# 其它
python3 m10_step3_away.py --no-voice           # 纯屏幕（识别与合成都不初始化）
python3 m10_step3_away.py --no-tts             # **只关语音合成，保留语音识别**
python3 m10_step3_away.py --focus-min 1        # 1 分钟番茄钟，方便测试
python3 m10_step3_away.py --preview out.png    # 不连板子，六态拼成一张图
```

### 语音命令（识别）—— 四条

识别模块 DFR0715（I2C 0x4F）。关键词在代码里用**空格分音的拼音**下发
（库只是逐字符发 ASCII，真正解析音节的是固件 —— 不分音节一次都认不出来且不报错）：

| 说 | 拼音（代码里的写法） | ID | 作用 |
|---|---|---|---|
| 开始学习 | `kai shi xue xi` | 1 | 开番茄钟（等价 A 键 / `/tmp/step3_trigger`） |
| 暂停学习 | `zan ting xue xi` | 2 | **手动暂停**倒计时（回座不会被自动解开） |
| 继续学习 | `ji xu xue xi` | 3 | 恢复倒计时（**能覆盖手动暂停**） |
| 停止学习 | `ting zhi xue xi` | 4 | 结束本次专注，淡回待机（等价 B 键） |

启动日志会列出全部命令，一眼确认四条都注册上了：

```
[语音] 识别模块就绪（I2C 0x4F），共 4 条命令：kai shi xue xi(→1) / zan ting xue xi(→2) / ji xu xue xi(→3) / ting zhi xue xi(→4)
[语音] 合成音量已设为 5
[语音] 合成模块就绪（I2C 0x40，V2）
```

识别到会打 `[语音] 识别到 ID = N`，随后是番茄钟的动作日志。

**⚠️ 手动暂停 vs 离座自动暂停必须分开记**（`FocusApp._manual_pause`）：
用户说「暂停学习」后即使走开再回来，离座监督的 `resume()` **不会**解开它 ——
否则用户的手动暂停会被静默吃掉。只有「继续学习」（`resume(force=True)`）能覆盖。

`FocusApp.pause()` 返回的是**字符串状态**而非布尔，用来区分措辞：

| 返回 | 含义 | 日志 |
|---|---|---|
| `"paused"` | 本次真的暂停了 | 手动暂停（来源）→ 倒计时冻结 |
| `"already"` | 已经在暂停中（手动 or 离座） | 已经在暂停中（来源）→ 不重复暂停（已标记为手动） |
| `"idle"` | 不在专注阶段，无效 | 未在专注中，暂停无效（来源） |

### 回座时「手动暂停」不会被假装恢复

这是条容易踩的坑：用户说过「暂停学习」后走开，回来时会走 `AwaySupervisor` 的回座分支。
`resume()` 被 `_manual_pause` 拦住返回失败 —— 此时**不能**照常出绿帧、播「欢迎回来」，
否则画面和语音都说恢复了，倒计时其实还冻着。

两条路径按 `resume()` 的真实返回值分流：

| 场景 | 绿帧 | 播报 | 日志 |
|---|---|---|---|
| 普通离座后回座 | ✅ 出 | 「欢迎回来」 | 回座（…）→ 番茄钟恢复 |
| **手动暂停**中回座 | ❌ 不出 | 「欢迎回来，计时还暂停着，说继续学习就恢复」 | 回座（…）→ 保持**手动暂停**，倒计时未恢复 |

### 语音合成（TTS）—— 默认开启

DFR0760（I2C 0x40，V2，音量 5）。**程序默认就会出声，不需要额外开关。**

启动日志里看到这两行就代表合成模块通了：

```
[语音] 合成音量已设为 5
[语音] 合成模块就绪（I2C 0x40，V2）
```

播报时机：

| 时机 | 播报内容 |
|---|---|
| 触发番茄钟 | 「好的，开始专注N分钟」 |
| **「暂停学习」** | 「已暂停，休息一下」 |
| **「继续学习」** | 「继续专注」 |
| **「停止学习」** | 「已结束本次专注」 |
| 专注结束 | 「专注结束，休息一下吧」 |
| 判离座（L1） | 「同学，你还在吗」 |
| L2 中提醒 | 「请回到座位」 |
| L3 强提醒 | 「计时已暂停，请回到座位」（间隔递增重复） |
| 回座（计时已恢复） | 「欢迎回来」 |
| 回座（**仍手动暂停**） | 「欢迎回来，计时还暂停着，说继续学习就恢复」 |

播完日志形如 `[语音] 播完（3.6s）：好的，开始专注25分钟` —— **有这一行才代表真的出声了**，
只有「待播」而没有「播完」说明模块没应答（查喇叭接线 / 供电 / I2C-UART 模式开关）。

### 暂时静音

**不用重启进程**，运行时一句话切换：

```bash
touch /tmp/step3_no_tts     # 静音：日志会打「已静音，跳过：xxx」，但不出声
rm    /tmp/step3_no_tts     # 恢复出声
```

⚠️ 静音文件在 `/tmp`，**板子重启会清空**，重启后自动恢复出声。
要持久关掉就用启动参数 `--no-tts`。

- 只影响**语音合成**；语音识别、番茄钟、离座监督、屏幕全部照常。
- 判断在 `Speaker.say()` 里做，所以**连合成帧都不会发**，不占用 I2C。
- `--no-tts` 是启动级开关（**连模块都不初始化**）；文件钩子是运行级开关，两者可叠加。

### 调试钩子

| 文件 | 作用 |
|---|---|
| `/tmp/step3_trigger` | `touch` 一下 = 识别到「开始学习」（不用重启进程） |
| `/tmp/step3_pause` | `touch` 一下 = 识别到「暂停学习」 |
| `/tmp/step3_resume` | `touch` 一下 = 识别到「继续学习」 |
| `/tmp/step3_stop` | `touch` 一下 = 识别到「停止学习」 |
| `/tmp/step3_absent` | 存在 = **强制判离座**（二哈在线时也生效，方便在真机上验证三档画面）；删掉 = 回退到真实传感器 |
| `/tmp/step3_present` | 存在 = **强制判在场**（用来验证回座绿帧，不用真的把脸凑上去） |
| `/tmp/step3_no_tts` | 存在 = **暂时静音**（只停语音合成，识别与番茄钟照常）；删掉立刻恢复 |

> 前四个是**一次性**钩子：主循环发现文件就删掉再执行，所以 `touch` 一下 = 触发一次，
> 不用手动清理。它们和语音、A/B 键走的是**同一组处理函数**（`trigger` / `cmd_pause` /
> `cmd_resume` / `cmd_stop`），假不了。
>
> `step3_absent` / `step3_present` 是**状态型**开关，优先级最高、排在二哈之前。
> 所以在没有二哈、或者想精确复现「离座 → 三档升级 → 回座」整条链时，都能用同一条路。
>
> 注意 `step3_absent` 只是「强制离座」，**删掉它不会变成在场** —— 那只是把判断权交回
> 真实传感器。想强制在场要用 `step3_present`。

## 7. 日志怎么看

```
[在座] 当前来源：二哈识图 I2C 0x32 · 人脸识别
[在座] 二哈心跳：已读 60 次 / 看到人脸 58 次 / 没人 2 次 / 错误 0
[离座] 63 秒没人 → L1 轻提醒，**番茄钟已暂停**
[离座] 已 190 秒（>3 分）→ L2 中提醒
[离座] 已 315 秒（>5 分）→ L3 强提醒
[离座] 回座（本次离开 330 秒，累计 330 秒）→ 番茄钟恢复
```

- `[在座] 二哈心跳` 每 30 秒一行，**直接告诉你相机到底看没看到人** ——
  「看到人脸 0 次」就说明是摄像头角度/光照问题，不是程序问题。
- `[在座] 二哈不可用（…）→ 退回触发文件模拟` = 二哈没接上或没锁成 I2C 协议，
  此时用 `/tmp/step3_absent` 手动驱动，屏幕逻辑照样能验。
- `[在座] 连续失败 20 次，停止轮询` = 跑到一半掉线，之后**不再判离座**
  （避免把用户误判成离座）。

## 8. 性能

离座帧的元素很少（1 个相机图标 + 1 条色带 + 人形 + 数字），
文字全部走第 2 段的**精灵缓存**（缓存 key 里不含逐帧变化的颜色/字号），
每帧只 paste。脉冲用 alpha 合成查表实现，不产生新 key。

已知天花板仍在贴屏：`unihiker/GUI.py` 每次 `config(image=…)` 重建
`ImageTk.PhotoImage`，约 42ms，理论上限约 24fps。要突破得直写 `/dev/fb0`。

运行环境：行空板 M10 板载 Python 3.7.3 + Pillow 9.0.1 + pinpong 0.6.x
